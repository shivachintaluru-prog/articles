The curious case of CLI UX

The ugliest interface I’ve used in years is the one I can’t stop opening.

No colours. No icons. No menus. No reassuring blue button telling me what to click next. Just a blinking cursor and a black box.

I’ve been in Claude Code 6–7 days a week. Building automations. Building ideas. Mostly just learning. For the first time in my PM career, I’m coding.

Six days is too short to be sure of any of this. I’m writing it down anyway because the shift has been violent enough that I don’t want to forget what it felt like before.

Every UX heuristic I’ve been taught says this shouldn’t work. It does.

The first thing I noticed is how much the chat box had been training me to wait.

When I’m in ChatGPT, the loop is: send a message, get an answer almost instantly, respond, repeat. Logan Kilpatrick made this point on Lenny’s podcast. The synchronous loop is a fine fit for short questions, and a terrible fit for tasks that need real reasoning time. The interface trains the ask. If the box says “type and wait,” I only ever typed things short enough to wait for.

What flipped wasn’t the black box itself. It was the run length. The moment a model can work for twenty minutes on one instruction, the synchronous chat loop becomes the wrong shape for it — terminal, Slack bot, or web app. The CLI just happened to be the first place I felt it, because it ships with no affordances pulling me back into the synchronous habit.

I write intent. I hit return. I walk away. Sometimes for two minutes, sometimes twenty. When I come back there’s a working thing.

It stopped feeling like chat. It started feeling like handing work off.

That’s the contract I have with a colleague: give me the task, tell me when you want it back, leave me alone in between. I didn’t realise how much I wanted that from an AI tool until I had it. The chat box was the right shape for short questions. It was never the right shape for delegation.

The second thing I noticed is what the colours were doing in the first place.

Every UX component I’ve shipped — buttons, dropdowns, progress bars, the disabled state on the Save button — exists to enforce a script. Buttons tell the user what they’re allowed to ask for. Dropdowns tell them when.

Vibecoding doesn’t need most of that script. I describe. It builds. I review. Two moves. Three if I reject and try again.

Once the model reads intent, most components become friction. The ones that survive (the approval prompt before a destructive command, the plan I can interrupt) earn it because they protect me from the agent, not from myself. That’s a much smaller surface area than the click-era IDE was built for.

Claude Code doesn’t ship with most of a script. That’s what’s strange about it.

The third thing I noticed is the dopamine.

ChatGPT’s product team has said publicly that how a model feels, not how it benchmarks, drives a surprising share of retention. Nick Turley on Lenny’s podcast treats it as a first-class product metric. I rolled my eyes the first time I read it.

I get it now. The vibe of Claude Code isn’t the colour scheme. It’s the loop. Type intent. Get a working thing I couldn’t have shipped before. Type the next. Get another. By the third one in a session, my brain has wired the loop. By day 4, I was checking the terminal in airport queues.

That high doesn’t come from a chat sidebar watching me type. It comes from walking away and coming back to something I couldn’t have built. I’m only saying this because I felt it in my own hands this week.

Dhanji Prasanna, CTO of Block, told a story on Lenny’s podcast that sounded outlandish until I started living in Claude Code. One of his engineers runs Goose, Block’s open-source agent, in always-on mode. The engineer mentions a feature in Slack. A few hours later there’s a PR for it on GitHub. Prasanna’s team has gone from 5-minute Goose sessions to hours of autonomous operation. I can’t verify the hours-saved number his team reports, but the shape of the loop he describes is the one I’m starting to feel.

The fourth thing is what Claude Code did to a feeling I’ve carried for a decade.

The pent up energy that always stopped PMs wasn’t fear. At least, mine wasn’t. It was the interface.

I’ve opened VS Code, read three lines of someone else’s code, felt the weight of “I should know what these brackets mean by now,” and closed the tab. More times than I want to say. Cursor helped. Replit helped. The chat sidebar helped. None of them removed the part where the IDE was still teaching me to write code in the margins, with autocomplete and red squigglies that all said the same thing: you’re not really one of the people this interface is for.

Claude Code worked for me because all it asked me to do was describe what I wanted. That’s the first time I’ve been one of the people an interface like that is for.

Alexander Embiricos has said memorising syntax matters less now, and being able to say what you want matters more. Code reading and debugging still do. I’m still learning to read what Claude gives me back, and six days hasn’t taught me that yet.

I described a Slack bot. It built it. I described an automation that scrapes a feed and posts to a channel. It built it. Neither is interesting. Both are things I would never have shipped on my own before this week, because the IDE kept asking me to be someone I’m not.

Who knew colours and UX components are this much distracting.

The hard part isn’t figuring out why this works. It’s admitting how much of the old UI I never needed.

The slate we all started to write from was there the whole time. Most of us got handed Figma instead.
